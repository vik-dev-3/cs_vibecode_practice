# CLAUDE.md

Учебный проект, который делаем как настоящий продукт. Цель — пройти полный жизненный цикл приложения, а не бизнес.

## Кто пользователь
- Вайб-кодер с техническим бэкграундом (терминал, Git, SQL, HTTP/API, Docker, безопасность, LLM-приложения — на уровне основ). Код руками не пишет: принимает решения, ревьюит, проверяет.
- **Режим обучения, всегда на русском.** Каждый шаг: что делаем, зачем, альтернативы, на что смотреть при ревью.
- Когда применяем хорошую практику — коротко назвать её и зачем она.

## Продукт
Командная AI-база знаний: рабочие пространства с ролями (owner/admin/member), заметки, загрузка документов (PDF, md), фоновая индексация, AI-чат по документам пространства (RAG) со стримингом и ссылками на источники, тарифы free/pro, приглашения по почте, публичный API с ключами.

## Стек
- Next.js (App Router) + TypeScript strict; Zod на всех границах (запросы, env, вебхуки, ответы LLM)
- Postgres + pgvector, Drizzle ORM + миграции
- Better Auth: email+пароль, GitHub OAuth
- Redis + BullMQ; воркер — отдельный сервис
- Cloudflare R2 (presigned URL)
- Vercel AI SDK: Claude основной, OpenAI запасной
- Resend, Stripe (test mode), Sentry
- Локально: Docker Compose (Postgres+pgvector, Redis)
- Деплой: Railway (app, worker, Postgres, Redis; окружения staging и production); CI — GitHub Actions
- Домен: только поддомен `lab.<домен>` на Cloudflare, основной домен не трогаем
- Node зафиксирован (`.nvmrc` + `engines`), lockfile всегда в git

## Документация

## Процесс
- Этап = ветка → PR → зелёный CI → merge в `main` → деплой. Прямых коммитов в `main` нет.
- Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `test:`…), коммиты маленькие.
- Одна сессия = один этап/задача.
- План перед кодом для всего, что больше пары файлов. Ждать «го».
- Маленькие шаги: шаг → пользователь проверяет → коммит.
- Конец этапа: итог, «что я узнал», чек-лист «проверить руками», обновить ROADMAP, новые ADR, сказать «пора начать новый чат».

## Правила
- **Секреты:** никогда не просить в чат и не выводить. Только `.env` (в `.gitignore`), переменные Railway, менеджер паролей. В репо — `.env.example` без значений. `.env*` читать запрещено.
- **Чужие сервисы:** регистрации, оплаты, ввод ключей делает пользователь по инструкции. Каждый раз напоминать: включить 2FA и лимит расходов, где есть оплата.
- **БД:** схема меняется только миграциями. Перед применением показать, что миграция меняет. Перед опасными действиями — бэкап. Никаких команд с записью в боевую базу.
- **Деструктивные команды** — только после явного «да».
- **Зависимости:** каждая новая — объяснить зачем и почему нельзя без неё; проверить, что пакет существует и популярен (npm, GitHub, загрузки).
- **Безопасность с первого дня:** проверка прав на каждый объект (workspace scoping), валидация ввода, rate limit, без stack trace наружу, защитные заголовки.
- **Тесты** обязательны на логику с правами доступа и деньгами.

- `npm run typecheck` — генерация типов роутов + `tsc --noEmit`
- `npm run build` — продакшн-сборка
- Node 24 (`.nvmrc`), пакетный менеджер — npm
