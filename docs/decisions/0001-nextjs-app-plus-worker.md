# 0001. Next.js-приложение + отдельный воркер в одном репозитории

- Статус: Принято
- Дата: 2026-10-30

## Контекст
Нужны UI, HTTP API и долгие фоновые задачи (парсинг PDF, эмбеддинги — секунды и минуты). HTTP-запрос не должен ждать индексацию.

## Решение
Next.js (App Router) для UI и API. Фоновые задачи — отдельный процесс-воркер на BullMQ (очередь в Redis). Оба живут в одном репозитории и делят код (схема БД, типы), но деплоятся как два сервиса.

## Альтернативы
- **Отдельный бэкенд (NestJS/Fastify) + SPA** — два приложения и контракт между ними; для команды из одного человека лишняя работа.
- **Задачи прямо в API-роуте** — таймауты, потеря задачи при рестарте, нет ретраев.
- **Монорепо с turborepo/workspaces** — полезно при нескольких пакетах; пока хватит одного `package.json`. Пересмотрим, если зависимости воркера и приложения начнут конфликтовать.

## Последствия
+ Один язык, общие типы, одна CI.
+ Ретраи и статус задач из коробки (BullMQ).
− Нужен Redis и хостинг, где живёт долгоживущий процесс (см. 0004).
